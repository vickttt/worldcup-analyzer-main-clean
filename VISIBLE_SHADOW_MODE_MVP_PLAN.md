# Visible Shadow Mode MVP Plan

Date: 2026-06-21

Scope: MVP design only. This plan does not write code, modify UI, change Ranking, change recommendation logic, modify scores, alter data files, create branches, commit, or push.

## Goal

Expose the smallest useful Shadow Mode signal in the Portfolio Ranking table.

The user should be able to see, at a glance:

```text
Legacy Rank
Scenario Rank
Shadow Verdict
```

MVP means:

- no detail dialog changes
- no Scenario Score display
- no Tail Exposure display
- no Rank Difference display
- no Conflict Flags display
- no sorting change
- no recommendation change

## Non-Negotiable Boundaries

Do not modify:

- `strategy_score(...)`
- `evaluate_allocation(...)`
- `strategy_comparison(...)` sorting logic
- recommendation logic
- default recommendation
- production `score`
- data files

Do not display in MVP:

- Scenario Score
- Tail Exposure
- Rank Difference
- Conflict Flags
- Scenario Score component breakdown

## Required Metadata

Visible Shadow Mode MVP requires existing structured metadata:

```python
strategy["shadow"]["scenario_rank"]
strategy["shadow"]["shadow_verdict"]
```

Current Shadow Metadata v0.1 provides:

- `legacy_rank`
- `legacy_score`
- `scenario_rank`
- `scenario_score`
- `rank_difference`
- `shadow_verdict`
- `scenario_rank_reason`

MVP should read only:

- `scenario_rank`
- `shadow_verdict`

## Specific Function Changes

## 1. `portfolio_ranking_rows(...)`

Purpose:

- Add two display-only columns.

Current row construction:

```python
rows.append({
    "组合名称": ...,
    "主剧本": ...,
    ...
    "综合评分": strategy.get("score", "-"),
})
```

MVP change:

```python
shadow = strategy.get("shadow") or {}
rows.append({
    "组合名称": ...,
    "Scenario Rank": shadow.get("scenario_rank", "-"),
    "Shadow Verdict": shadow.get("shadow_verdict", "-"),
    ...
})
```

Recommended column placement:

```text
组合名称
Scenario Rank
Shadow Verdict
主剧本
让球资产
大小球资产
波胆资产
EV
ROI
最大亏损
剧本一致性评分
综合评分
```

Reason:

- Shadow fields should be visible near the rank identity.
- They should not be mixed into score columns.

Risk:

- LOW

Why:

- Pure display row formatting.
- Does not mutate strategy.
- Does not sort.
- Missing metadata can show `-`.

## 2. `render_portfolio_ranking(...)`

Purpose:

- Ensure shown strategies have `strategy["shadow"]`.
- Keep current sort unchanged.

Current sort must remain:

```python
comparison = sorted(comparison, key=lambda item: item.get("score", 0), reverse=True)
```

MVP options:

### Option A: Attach Metadata Before Rendering

Call Shadow helper before table formatting:

```text
comparison = attach_shadow_metadata(comparison, match, distribution)
```

Then keep:

```text
comparison sorted by legacy score
shown = comparison[:6]
```

Important:

- If helper is called here, it must return strategies in the same Legacy order.
- It must not change `score`.

Risk:

- MEDIUM

Why:

- This function controls displayed comparison and My Portfolio insertion.
- Safe if helper preserves order exactly.

### Option B: Attach Metadata Earlier

Attach metadata where `snapshot_strategies` are created:

```text
snapshot_strategies = strategy_comparison(...)
snapshot_strategies = attach_shadow_metadata(...)
```

Then `render_portfolio_ranking(...)` only reads metadata.

Risk:

- LOW to MEDIUM

Why:

- Cleaner separation.
- Avoids recomputing Shadow metadata during render.
- But requires integration near match detail flow.

Recommended MVP:

- Option B if implementing in the main runtime.
- Option A only if faster validation is needed and helper is proven order-safe.

## Risk Assessment

| Change | Risk | Notes |
| --- | --- | --- |
| Add columns in `portfolio_ranking_rows(...)` | LOW | Display only. |
| Read `strategy.get("shadow")` | LOW | Safe fallback to `-`. |
| Import `attach_shadow_metadata` | LOW | Isolated helper. |
| Attach metadata after `strategy_comparison(...)` | LOW to MEDIUM | Safe if order is preserved. |
| Attach metadata inside `render_portfolio_ranking(...)` | MEDIUM | Must not disturb My Portfolio comparison. |
| Change sort logic | HIGH | Not allowed. |
| Show Scenario Score / Tail / conflicts | MEDIUM | Not part of MVP. |
| Modify detail dialog | LOW to MEDIUM | Not part of MVP. |

Overall MVP risk:

```text
LOW to MEDIUM
```

Risk is LOW if:

- metadata is attached before rendering
- table only reads optional fields
- sort line remains unchanged

Risk becomes MEDIUM if:

- metadata is computed inside render path
- My Portfolio is included before Shadow helper and affects scenario ranks

## Is It Worth Doing?

Yes.

Reason:

- Three validation rounds showed `Legacy Rank 1 != Scenario Rank 1`.
- Users need to see this disagreement without replacing Legacy Ranking.
- MVP adds only two fields and preserves all production behavior.
- It creates immediate decision value with minimal code surface.

However:

- MVP should only be done after confirming `strategy["shadow"]` is available in the runtime strategies being displayed.
- If runtime strategies do not yet include `shadow`, first attach metadata after `strategy_comparison(...)`.

## Acceptance Criteria

MVP is acceptable when:

- Portfolio Ranking order is unchanged.
- Default recommendation is unchanged.
- `score` values are unchanged.
- Table displays `Scenario Rank`.
- Table displays `Shadow Verdict`.
- Missing Shadow metadata displays `-`.
- No Scenario Score is displayed.
- No Tail Exposure is displayed.
- No Rank Difference is displayed.
- No Conflict Flags are displayed.

## Final Recommendation

Implement the MVP.

Recommended minimal path:

1. Attach `strategy["shadow"]` after `strategy_comparison(...)`.
2. Add only `Scenario Rank` and `Shadow Verdict` to `portfolio_ranking_rows(...)`.
3. Keep `render_portfolio_ranking(...)` sorting unchanged.
4. Do not touch details, scoring, recommendation logic, or data files.
